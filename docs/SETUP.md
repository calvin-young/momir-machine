# Setup

There are two parts. You build the card catalog once on any computer. Then you copy the result to the Pi. Commands below run from the repo root.

## Build the catalog

The catalog is built from Scryfall's Oracle Cards bulk data. The pipeline has four scripts that run in order.

1. **Get the card data.** Download Scryfall's Oracle Cards bulk file and save it as `data/oracle-cards.jsonl.gz`. The script expects one card per line (JSON Lines), gzipped. **(confirm)** Scryfall's bulk file may be a JSON array, which won't parse line by line.
2. **Filter the cards.** Keeps castable paper creatures and drops tokens. Writes `data/oracle-cards-filtered.jsonl`.

   ```bash
   python3 01_filter_cards.py
   ```

3. **Download the art.** Saves each card's art crop to `img/raw/<oracle_id>.jpg`. Re-running skips files already downloaded.

   ```bash
   python3 02_download_images.py
   ```

4. **Process the art.** Converts each image to a 384-pixel-wide, 1-bit dithered PNG in `img/processed/`. Re-running skips files already processed, so delete the output folder to reprocess everything.

   ```bash
   python3 03_process_images.py
   ```

5. **Build the catalog.** Writes `data/catalog.json`, grouped by mana value. Cards without a processed image are skipped.

   ```bash
   python3 04_build_catalog.py
   ```

The art for the boot and status slips lives in `img/assets/`. It isn't generated by these scripts. Those processed PNGs were made by hand. **(confirm the process)**

Downloading the art (step 3) is the slow part, and it makes many requests to Scryfall. Keep `MAX_WORKERS` modest. You only need to redo it when the card set changes.

## On the Pi

The Pi runs the printer and the buttons, and it only reads the catalog.

Requirements:

- Raspberry Pi Zero W v1.1 with Raspberry Pi OS Lite (Trixie). Python 3.12 or newer is required. The code uses nested quotes inside f-strings, which older versions reject.
- The printer connected to the Pi's USB data port.
- The button, dial, and LED wired as in [HARDWARE.md](HARDWARE.md#pinout).

Copy these from the build machine to the same paths on the Pi:

- `data/catalog.json`
- `img/processed/`
- `img/assets/processed/`

Install the packages. `lgpio` comes from apt, so the virtual environment includes system packages.

```bash
sudo apt install python3-lgpio
python3 -m venv --system-site-packages .venv
source .venv/bin/activate
pip install python-escpos pillow
```

**(confirm)** How the program is started at boot, and whether it needs `sudo` for USB access or a udev rule. Neither is in the repo yet.

## Run it

Start the machine:

```bash
python3 main.py
```

It prints the startup slip, then loads the catalog, then prints the ready slip. The button works after that.

To look up a card by name, which prints only its front face:

```bash
python3 main.py "Card Name"
```

## Troubleshooting

- **"Could not write catalog cache"**: the Pi can't write `data/catalog.pkl`. The machine still runs, but startup stays slow.
- **Slow startup**: the first load parses `catalog.json` and writes `catalog.pkl`. Later starts load the pickle, which is faster.
- **"No creatures exist with these filters"**: no card matches the mana value and the current toggles. Check the dial, or turn off the Pauper toggle.
