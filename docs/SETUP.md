# Setup

There are two parts. You build the card catalog once on any computer. Then you copy the result to the Pi. Commands below run from the repo root.

## Build the catalog

The catalog is built from Scryfall's Oracle Cards bulk data. The pipeline has four scripts that run in order.

1. **Get the card data.** Download Scryfall's Oracle Cards bulk file and save it as `data/oracle-cards.jsonl.gz`. The script expects one card per line (JSON Lines), gzipped. **(confirm)** Scryfall's bulk file may be a JSON array, which won't parse line by line.
2. **Filter the cards.** Keeps castable paper creatures and drops tokens. Writes `data/oracle-cards-filtered.jsonl`.

   ```bash
   python3 01_filter_cards.py
   ```

3. **Download the art.** Saves each card's art crop to `img/raw/<oracle_id>.jpg`. Re-running skips files already downloaded.

   ```bash
   python3 02_download_images.py
   ```

4. **Process the art.** Converts each image to a 384-pixel-wide, 1-bit dithered PNG in `img/processed/`. Re-running skips files already processed, so delete the output folder to reprocess everything.

   ```bash
   python3 03_process_images.py
   ```

5. **Build the catalog.** Writes `data/catalog.json`, grouped by mana value. Cards without a processed image are skipped.

   ```bash
   python3 04_build_catalog.py
   ```

The art for the boot and status slips lives in `img/assets/`. It isn't generated by these scripts. Those processed PNGs were made by hand. **(confirm the process)**

Downloading the art (step 3) is the slow part, and it makes many requests to Scryfall. Keep `MAX_WORKERS` modest. You only need to redo it when the card set changes.

## On the Pi

The Pi runs the printer and the buttons, and it only reads the catalog.

Requirements:

- Raspberry Pi Zero W v1.1 with Raspberry Pi OS Lite (Trixie). Python 3.12 or newer is required. The code uses nested quotes inside f-strings, which older versions reject.
- The printer connected to the Pi's USB data port.
- The button, dial, and LED wired as in [HARDWARE.md](HARDWARE.md#pinout).

Copy these from the build machine to the same paths on the Pi:

- `data/catalog.json`
- `img/processed/`
- `img/assets/processed/`

Install the packages. `lgpio` comes from apt, so the virtual environment includes system packages.

```bash
sudo apt install python3-lgpio
python3 -m venv --system-site-packages .venv
source .venv/bin/activate
pip install python-escpos pillow
```

## Start at boot

The machine is meant to run from a power switch: flip it on, and the startup slip prints. A systemd service starts `main.py` at boot. It runs as root, which gives it access to the printer's USB device and the GPIO pins without a udev rule.

The service file is [system/momir.service](../system/momir.service). It assumes the repo is at `/home/calvin/momir`. If yours is somewhere else, change the four paths in it first.

```bash
mkdir -p .escpos-cache
ESCPOS_CAPABILITIES_PICKLE_DIR=$PWD/.escpos-cache .venv/bin/python -c "import escpos.printer"
sudo cp system/momir.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable momir.service
```

The second line builds python-escpos's printer database cache once. Without it, the library re-parses its database on every start, which takes about 8 seconds on a Pi Zero.

Check it with `systemctl status momir` and `journalctl -u momir`. The log shows how many seconds after boot the startup slip and the ready line were sent.

## Faster boot (optional)

With a stock Raspberry Pi OS Lite install, a Pi Zero W takes about two minutes to print the startup slip. With the changes below, it starts printing about 19 seconds after the power switch is flipped, and the ready line follows a few seconds later. WiFi and SSH still work. They come up later than the machine, about 80 seconds after boot.

The service file above already does part of this. It starts the program as soon as the SD card is mounted, without waiting for the network or the rest of the system. It also gives the program real-time priority until the ready line prints.

Make these changes on the Pi. Back up `/boot/firmware/config.txt` first.

**Firmware and kernel** (`/boot/firmware/config.txt`). Change or add these lines in the `[all]` section at the end:

```ini
boot_delay=0
disable_splash=1
initial_turbo=30
auto_initramfs=0
dtoverlay=disable-bt
gpu_mem=16
```

Near the top, set these, which are on by default:

```ini
dtparam=audio=off
camera_auto_detect=0
display_auto_detect=0
```

Also comment out `dtoverlay=vc4-kms-v3d` and `max_framebuffers=2` near the top.

| Setting | Effect |
| --- | --- |
| `auto_initramfs=0` | Skips the initramfs, which saves about 7 seconds. The SD card and ext4 drivers are built into the Raspberry Pi kernel, so it isn't needed. |
| `dtoverlay=disable-bt` | Turns off Bluetooth. Remove it if you need Bluetooth. WiFi isn't affected. |
| `gpu_mem=16` | Loads the smaller GPU firmware. Fine with no display or camera. |
| `vc4-kms-v3d` commented out | Skips loading the display driver. Fine without a display. |
| `boot_delay`, `disable_splash`, `initial_turbo` | Shorten the firmware stage. |
| `audio`, `camera_auto_detect`, `display_auto_detect` off | Skip probing hardware the machine doesn't have. |

**If the Pi doesn't boot after this**, put the SD card in any computer, open `config.txt` on the boot partition, and set `auto_initramfs=1` again.

**Kernel messages** (`/boot/firmware/cmdline.txt`). Add `quiet loglevel=3` to the end of the line. The file must stay a single line.

**Swap.** Turn it off. The program uses about 140 MB of the Pi Zero's 512 MB.

```bash
sudo mkdir -p /etc/rpi/swap.conf.d
printf "[Main]\nMechanism=none\n" | sudo tee /etc/rpi/swap.conf.d/90-no-swap.conf
```

**Services you don't need.** None of these are needed for WiFi or SSH.

```bash
sudo systemctl disable keyboard-setup.service console-setup.service rpi-eeprom-update.service sshswitch.service getty@tty1.service NetworkManager-wait-online.service bluetooth.service e2scrub_reap.service
sudo systemctl disable apt-daily.timer apt-daily-upgrade.timer apt-listchanges.timer man-db.timer
```

The timers don't slow the boot itself, but they run package and manual-page jobs in the background while the machine is in use. Run `sudo apt update && sudo apt upgrade` by hand now and then instead.

**cloud-init.** Raspberry Pi Imager uses it to apply your settings on the first boot. After that it only costs time.

```bash
sudo touch /etc/cloud/cloud-init.disabled
sudo systemctl mask cloud-init-local.service cloud-init.service cloud-config.service cloud-final.service
```

`getty@tty1` is the login prompt on a monitor. Leave it enabled if you plug one in. Leave NetworkManager, wpa_supplicant, ssh and systemd-rfkill alone: WiFi and SSH depend on them.

**Keep the filesystem check.** A power switch cuts power without a clean shutdown, and the check at boot repairs the SD card's filesystem after that.

Reboot, then check `journalctl -u momir` for the boot times.

## Run it

Start the machine:

```bash
python3 main.py
```

It prints the startup slip, then loads the catalog, then prints the ready slip. The button works after that.

To look up a card by name, which prints only its front face:

```bash
python3 main.py "Card Name"
```

## Troubleshooting

- **"Could not write catalog cache"**: the Pi can't write `data/catalog.pkl`. The machine still runs, but startup stays slow.
- **Slow startup**: the first load parses `catalog.json` and writes `catalog.pkl`. Later starts load the pickle, which is faster.
- **Startup still slow after the steps above**: check that `.escpos-cache/` holds a `.capabilities.pickle` file, and that `data/catalog.pkl` exists. The service can't write these in the first seconds of boot, while the SD card is still read-only.
- **"No creatures exist with these filters"**: no card matches the mana value and the current toggles. Check the dial, or turn off the Pauper toggle.
